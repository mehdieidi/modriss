# Evaluation scenarios

## Reference fixture

Use separate clean application datasets for independent scenarios; S01–S03 form an explicit sequential story. Preserve preprovisioned identity accounts while resetting products, orders, payment/notice records, audit and replay state. A controlled application clock and deterministic provider/email ledgers are experiment facilities. Use sandbox payment tokens only.

| Item                     | Value                                                                                                                                                   |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Time T0                  | `2027-05-10T09:00:00Z`; display timezone UTC                                                                                                            |
| Product N1               | Notebook; price 500 USD cents; revision 1; available 3                                                                                                  |
| Product P1               | Pen; price 200 USD cents; revision 1; available 5                                                                                                       |
| Product C1               | Greeting card; price 300 USD cents; revision 1; available 0                                                                                             |
| Catalogue initialization | Create each product at zero stock; add the stated quantities through staff stock-addition commands                                                      |
| Alice / Ben              | Distinct verified customer identities and test emails                                                                                                   |
| Staff / services         | Nora with staff role; distinct due-processing and authenticated provider identities                                                                     |
| Alice's basket           | N1 quantity 2 + P1 quantity 1; quoted revision/prices above; total 1200 cents                                                                           |
| Alice's hold             | Checkout commits at T0; expiry exactly `2027-05-10T09:15:00Z`                                                                                           |
| Provider modes           | Timely capture, final decline/unpaid, delayed/dropped/duplicate facts, wrong amount/currency, timeout after acceptance, failed/pending/completed refund |
| Provider ledgers         | Record stable session, capture and refund keys and external effects independently of application records                                                |
| Email modes              | Accept, fail before acceptance, timeout after acceptance, duplicate-key acceptance                                                                      |

Assign unique keys to fresh customer/staff operations. Preserve each original key/payload/validity window for replay tests. Use explicit ordering or a recorded concurrency schedule for races. Move the controlled clock rather than waiting real minutes or thirty days. When testing local timezone presentation, keep the underlying instants equal and show the chosen timezone explicitly.

## Proposed expert and user activities

These materials are a starting point for a piloted protocol, not a validated experiment or a claim of statistical validity. Give model-building participants requirements first and withhold the reference XMI until their task is complete.

| Activity                 | Task                                                                                                                                             | Evidence                                                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| Domain comprehension     | Explain Alice's total, Ben's expired-but-charged outcome, and cancellation racing readiness                                                      | Accuracy, misconceptions, time and clarification requests                                                             |
| Bounded CIM construction | From an empty model, represent checkout, atomic stock rules and payment expiry/late-capture compensation                                         | Time, model coverage, validation results, help requests and corrections                                               |
| Reference inspection     | Import the CIM, locate R05/R07/R10/R21, identify the consistency boundary and predict S08/S10                                                    | Navigation success, explanation quality, predicted outcomes and time                                                  |
| PIM/PSM review           | Generate a PIM draft, refine inventory transactions, authenticated provider facts, durable refund work and timers; continue to AWS PSM/artifacts | Trace links, unresolved/resolved decisions, model revisions, changed generated artifacts and lost/preserved semantics |
| End-user runtime task    | Execute Alice's order/pickup and a cancellation/refund example after implementation                                                              | Correct outcomes, comprehension, task completion/time and facilitator intervention                                    |
| Controlled evolution     | In a separate copy change the hold from fifteen to ten minutes; trace impact to expiry, session deadlines, late capture, UI and boundary tests   | Correct impacts, revised models/tests, regenerated changes and preserved manual refinements                           |

Pilot task size and duration; participants need not construct every helper element in the full reference. Keep training, starting artifacts, assistant availability, task wording, clock, provider faults and datasets comparable across conditions. Record prior modeling/cloud experience, unsuccessful tasks and assistance; counterbalance task order if comparing conditions. Keep modeling quality, tool usability, amount of manual implementation and runtime correctness as separate observations.

## End-to-end evidence chain

1. Import, inspect, save/export/reimport and explicitly validate the CIM; inspect requirement-to-business references.
2. Generate/review the PIM. Complete atomic data changes, immutable receipt contracts, identity filtering, provider fact verification, durable obligations, retries/timers and settlement-dependent retention. Explicitly validate the refined model.
3. Generate/review the AWS PSM, checking persistence, transaction support, permissions, provider integration, schedules, retries, erasure and observability. Explicitly validate the reviewed model.
4. Generate artifacts, inspect manual actions/protected regions, implement business logic and the controlled provider/clock facilities, then build and deploy to the test environment.
5. Execute scenario oracles and retain requirement IDs, trace links, model revisions, generated versus completed code differences, validation/test reports, provider ledgers and workload measurements.

Record repository revision, sample hash, tool/configuration versions, deployment details and fault schedule. Passing an ETL/generation command is evidence for that pipeline step; it is not evidence that checkout, refund or inventory acceptance tests passed.
