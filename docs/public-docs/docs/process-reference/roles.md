# Process roles

Roles identify responsibilities and decision authority. They do not prescribe team size. One person may hold several roles, and a larger team may distribute one role across people. The method profile records assignments, collaboration and any independence required for review.

| Role                     | Responsibility                                                                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Sponsor                  | Decides on resources, continuation, redirection or stopping the project, and participates in product closure.                               |
| Product owner            | Sets desired outcomes, requirement priorities, increment and release scope, and reviews acceptance and release results.                     |
| Domain expert            | Explains business concepts, rules and scenarios, and checks the team's interpretation of the domain.                                        |
| Method engineer          | Tailors the process, maintains the method profile and improves it using project experience.                                                 |
| Delivery lead            | Coordinates assignments, ownership, dependencies, blockers and the capacity shared by development and service work.                         |
| Business modeler         | Creates and completes the CIM, including goals, participants, capabilities, domain structure and behavior.                                  |
| Requirements engineer    | Defines requirements, acceptance criteria and constraints, and maintains their links to goals and model elements.                           |
| Solution architect       | Completes the PIM and decides service boundaries, contracts, data, integration and failure behavior. Reviews the CIM-to-PIM transformation. |
| Cloud platform engineer  | Leads provider mapping, PSM completion, environment preparation and generation.                                                             |
| Application engineer     | Implements business logic, adapters and tests while respecting generated-file ownership.                                                    |
| Quality engineer         | Defines the test approach and correctness criteria, prepares verification evidence and follows up quality findings.                         |
| Security engineer        | Reviews threats, privacy, permissions and security controls. Records security exceptions with reasons, owners and review dates.             |
| Cost analyst             | Examines usage assumptions, estimates, budgets and actual cost deviations, and feeds the results into product and architecture decisions.   |
| Release engineer         | Prepares the release candidate, build and deployment pipeline, deployment and recovery plans, and release records.                          |
| Service owner            | Defines service objectives, monitoring, response and support. Accepts operational readiness and leads service operation.                    |
| Process reviewer         | Reviews evidence and acceptance conditions, records process decisions and follows up improvements.                                          |
| Records and data steward | Manages retention, transfer, archival and deletion obligations, including their disposition at product closure.                             |

Stakeholders take part in domain discovery, acceptance criteria and outcome reviews, directly or through the product owner and domain expert. Combining job titles does not remove any of these responsibilities.
