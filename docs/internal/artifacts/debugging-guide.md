# Debugging Generated AWS Artifacts

This guide explains how to locate the root cause of a failure in a project
generated by the complete CIM -> PIM -> AWS PSM -> artifacts pipeline. Use it
after reproducing a problem with the process in
[deployment-and-testing.md](deployment-and-testing.md).

The central rule is:

> Edit a generated artifact only to prove a hypothesis. Make the permanent fix
> in the protected region, source model, transformation, or generator that owns
> the faulty content.

## 1. Preserve the Failure

Before changing anything, retain:

- the exact CIM, PIM, and PSM XMI files;
- the downloaded artifact ZIP and its extracted directory;
- the failing command, complete output, HTTP request, and response;
- backend, frontend, LocalStack, Lambda, and CloudFormation logs;
- the Git commit and versions of Java, Maven, Docker, AWS CLI, SAM CLI, and Go.

Run generation twice from the same input into clean directories and compare the
results. A difference outside protected regions indicates a determinism defect.

```powershell
Get-FileHash .\first.zip, .\second.zip -Algorithm SHA256
git diff --no-index -- .\first-extracted .\second-extracted
```

Reduce the source model to the smallest model that still reproduces the issue.
This usually reveals which model element or relationship triggers the failure.

## 2. Identify the Owning Layer

Classify the failure before editing code:

| Observation                                                      | Most likely owner                                                                     |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| CIM -> PIM fails or PIM contains incorrect concepts              | `mde/transformations/cim-to-pim`                                                      |
| PIM -> PSM fails or PSM contains an incorrect AWS mapping        | `mde/transformations/pim-to-awspsm`                                                   |
| Artifact generation fails before producing the ZIP               | EGX orchestration, EGL/EOL, or invalid PSM                                            |
| A file is missing, duplicated, or at the wrong path              | `awspsm2artifacts.egx`, `paths.eol`, or an EGX guard                                  |
| Correct PSM produces incorrect artifact text                     | EGL template or shared generator EOL library                                          |
| The same incorrect value appears in many artifact types          | shared EOL library, usually `contracts.eol`, `cfn.eol`, `values.eol`, or `naming.eol` |
| Generated artifact is valid but customized business logic fails  | developer-owned protected region                                                      |
| Artifact works on AWS but not LocalStack                         | LocalStack compatibility or configuration                                             |
| Artifact fails both SAM/AWS validation and LocalStack deployment | generator or source-model defect                                                      |

Do not classify unimplemented protected-region logic as a generator defect.
Check `generated/reports/manual-actions.md` and
`generated/trace/protected-regions.json` first.

## 3. Trace a Bad Artifact to Its Source

Every generated project contains machine-readable trace data:

- `generated/trace/artifact-trace.json`: artifact path -> generator rule and
  source stable IDs;
- `generated/trace/model-trace.json`: deployed logical ID -> PSM metaclass,
  stack, and source stable ID;
- `generated/trace/protected-regions.json`: protected region -> artifact,
  source stable ID, owner, and completion state;
- `generated/reports/generation-report.md`: generation summary;
- `generated/reports/manual-actions.md`: required developer actions.

### Start From a File

Run this from the extracted generated-project root:

```powershell
$path = 'template-example-deployment-unit.yaml'
$trace = Get-Content .\generated\trace\artifact-trace.json -Raw |
  ConvertFrom-Json
$artifact = $trace.artifacts | Where-Object path -eq $path
$artifact | Format-List path, artifactKind, generatedBy, sourceStableIds
```

The `generatedBy` value is the owning EGX rule. Locate the rule and its EGL
template from the Modless repository root:

```powershell
$rule = $artifact.generatedBy
rg -n -F $rule .\mde\generation\awspsm-to-artifacts
rg -n -F 'the incorrect literal value' `
  .\mde\generation\awspsm-to-artifacts .\mde\transformations
```

Inspect the EGX rule in
`mde/generation/awspsm-to-artifacts/awspsm2artifacts.egx`, then inspect its
`template` and any EOL operations called by that template.

Use each `sourceStableIds` value to find the responsible PSM element and trace
it upstream:

```powershell
$stableId = $artifact.sourceStableIds[0]
rg -n -F $stableId .\path\to\model.awspsm.xmi .\path\to\model.pim.xmi
```

If the PSM element is correct, fix the generator. If the PSM element is already
wrong, trace and fix the PIM -> PSM transformation instead.

### Start From an AWS Logical ID

CloudFormation and runtime errors usually report a logical resource ID. Resolve
it through `model-trace.json`:

```powershell
$logicalId = 'ReportedLogicalId'
$modelTrace = Get-Content .\generated\trace\model-trace.json -Raw |
  ConvertFrom-Json
$resource = $modelTrace.resources |
  Where-Object logicalId -eq $logicalId
$resource | Format-List logicalId, metaclass, stack, stableId
```

Search the reported `stableId` in the PSM and transformation sources. Search
the `metaclass` in `cfn.eol`, `sam.eol`, and the relevant EGL template to find
the serializer responsible for the resource.

### Start From a Protected Region

```powershell
$regions = Get-Content .\generated\trace\protected-regions.json -Raw |
  ConvertFrom-Json
$regions.regions |
  Where-Object { $_.filled -eq $false -or $_.artifactPath -eq 'path/to/file' } |
  Format-Table artifactPath, regionId, sourceStableId, ownerHint, filled
```

If the failing behavior belongs to an unfilled developer-owned region, implement
that region and regenerate to verify that preservation works. Do not place the
business logic into an EGL template.

## 4. Diagnose by Failure Stage

### Transformation or Generation Request Fails

Capture the backend log entry with its `requestId`, exception type, and stack
trace:

```powershell
docker compose logs --since=10m backend |
  Select-String 'requestId|Exception|ERROR|WARN'
```

For an XMI root error, inspect the generated XMI for detached or extra root
objects. A valid transformation output must contain exactly one model root.
Fix the ETL rule that creates an unattached object or fails to attach/delete a
temporary object, then add an ETL regression test.

For an EGX/EGL exception, start with the named EGX rule/template and source
stable ID. The Java entry point is:

`packages/java/mde-m2t-runner/src/main/java/io/mehdieidi/modless/mde/generation/EpsilonEgxGenerator.java`

### Static Validation Fails

Run the narrowest validator first:

```powershell
sam validate --lint --template-file .\template-<deployment-unit>.yaml

Get-ChildItem .\asl\*.json | ForEach-Object {
  aws --endpoint-url http://localhost:4566 stepfunctions `
    validate-state-machine-definition --definition file://$($_.FullName)
}

go test ./...
```

Map a validation error to the artifact trace, then to its EGX rule and source
stable ID. Duplicate OpenAPI paths/statuses, invalid ASL targets, malformed
CloudFormation properties, and invalid schemas generally belong in generator
helpers or in the transformation that assembled their PSM definitions.

### CloudFormation or SAM Deployment Fails

Set credentials and bypass the proxy for local endpoints:

```powershell
$env:AWS_ACCESS_KEY_ID='test'
$env:AWS_SECRET_ACCESS_KEY='test'
$env:AWS_DEFAULT_REGION='us-east-1'
$env:AWS_ENDPOINT_URL='http://localhost:4566'
$env:NO_PROXY='localhost,127.0.0.1'
$env:no_proxy=$env:NO_PROXY
```

Inspect failed stack events, then resolve the reported logical ID using
`model-trace.json`:

```powershell
aws --endpoint-url http://localhost:4566 cloudformation describe-stack-events `
  --stack-name <stack-name> `
  --query "StackEvents[?ResourceStatus=='CREATE_FAILED' || ResourceStatus=='UPDATE_FAILED'].[LogicalResourceId,ResourceType,ResourceStatusReason]"

aws --endpoint-url http://localhost:4566 cloudformation get-template `
  --stack-name <stack-name>

docker compose logs --since=10m localstack
```

An AWS validation error is authoritative. A LocalStack-only implementation
error should be confirmed against AWS documentation or a disposable AWS test
account before changing the generator.

### Lambda Runtime Fails

Invoke the function directly before testing its trigger:

```powershell
aws --endpoint-url http://localhost:4566 lambda get-function-configuration `
  --function-name <function-name>

aws --endpoint-url http://localhost:4566 lambda invoke `
  --function-name <function-name> `
  --payload fileb://.\events\<event>.json .\response.json

aws --endpoint-url http://localhost:4566 logs tail `
  /aws/lambda/<function-name> --since 10m
```

Generated handlers include source stable IDs in tracing/logging. Use that ID to
locate the PSM element. Distinguish generated adapter/configuration failures
from failures inside a developer-owned business-logic protected region.

### Step Functions Execution Fails

```powershell
aws --endpoint-url http://localhost:4566 stepfunctions describe-execution `
  --execution-arn <execution-arn>

aws --endpoint-url http://localhost:4566 stepfunctions get-execution-history `
  --execution-arn <execution-arn> --reverse-order
```

Use the failed state name to find the state in `asl/*.json`. Then trace that
artifact to its rule and source stable ID. Typical root causes are an incorrect
Task resource, missing CloudFormation substitution, invalid result path, or a
Lambda output that violates the workflow contract.

### API or Event Trigger Fails

First prove that the target Lambda works by direct invocation. Then inspect the
trigger:

```powershell
aws --endpoint-url http://localhost:4566 apigateway get-rest-apis
aws --endpoint-url http://localhost:4566 apigateway get-resources `
  --rest-api-id <api-id>
aws --endpoint-url http://localhost:4566 events list-rules
aws --endpoint-url http://localhost:4566 sns list-topics
aws --endpoint-url http://localhost:4566 sqs list-queues
```

This separates handler defects from API Gateway, EventBridge, SNS, or SQS
wiring defects.

## 5. Make the Permanent Fix

Use this decision:

1. If the PSM is wrong, fix `mde/transformations/pim-to-awspsm` and add an ETL
   regression test.
2. If the PSM is correct but the artifact is wrong, fix
   `mde/generation/awspsm-to-artifacts/awspsm2artifacts.egx`, its EGL template,
   or a shared EOL library and add an M2T regression test.
3. If the artifact and AWS behavior are correct but LocalStack fails, document
   or isolate the LocalStack limitation; do not weaken valid AWS output.
4. If required business behavior is absent from a protected region, implement
   the region and verify it survives regeneration.

Prefer the smallest shared fix that expresses the correct rule. Avoid
artifact-specific string replacements and special cases tied to sample names.

## 6. Verify the Fix

Regenerate from the original failing model, prove the original command now
passes, and verify that an unrelated representative model still works.

Run the relevant regression suites from the Modless repository root:

```powershell
mvn -pl packages/java/mde-etl-runner -am `
  "-Dtest=PimToAwsPsmEtlRegressionTest" `
  "-Dsurefire.failIfNoSpecifiedTests=false" test

mvn -pl packages/java/mde-m2t-runner -am `
  "-Dtest=EpsilonEgxGeneratorTest,AwsPsmArtifactGenerationSyntaxTest" `
  "-Dsurefire.failIfNoSpecifiedTests=false" test

mvn -pl packages/java/platform-application -am `
  "-Dtest=TransformationServiceTest" `
  "-Dsurefire.failIfNoSpecifiedTests=false" test
```

Then execute the full validation, deployment, and runtime process in
[deployment-and-testing.md](deployment-and-testing.md).
A fix is complete only when the regression test and the final generated project
both pass.

## 7. Common Root-Cause Examples

| Symptom                                            | Trace path                                                            | Correct fix location                                                  |
| -------------------------------------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `Uploaded XMI must contain exactly one model root` | output XMI -> extra root object -> creating ETL rule                  | ETL rule lifecycle/containment plus one-root regression test          |
| Duplicate OpenAPI `400` response                   | OpenAPI file -> artifact rule -> source route -> generated definition | PIM -> PSM API mapping or `contracts.eol`, plus duplicate-status test |
| CloudFormation secret resolution failure           | failed logical ID -> `model-trace.json` -> PSM secret                 | secret transformation or CloudFormation serializer                    |
| Step Functions reports invalid `FunctionName`      | execution state -> ASL file -> source workflow state                  | ASL contract generation and CloudFormation substitutions              |
| Manual handler returns `NOT_IMPLEMENTED`           | Lambda log -> protected-region trace                                  | developer-owned protected region                                      |
